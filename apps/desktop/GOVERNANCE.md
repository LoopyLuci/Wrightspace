# WebBuilder Governance Model

## Mission

WebBuilder exists to empower anyone to build for the web, forever.

## Principles

1. **Open by default** — Code, formats, and processes are open
2. **Community owned** — No single entity controls the platform
3. **Backward compatible** — Old projects always work
4. **Extensible** — Anyone can add capabilities
5. **Accessible** — Free to use, available to everyone

## Structure

### Core Team
- Maintains the core library
- Reviews and merges contributions
- Sets the roadmap
- Elected by community annually

### Contributors
- Anyone who contributes code, docs, designs, or testing
- Earns voting rights after sustained contribution
- Can propose changes via RFC process

### Plugin Authors
- Independent developers who build plugins
- Full control over their plugins
- Can use any license for their plugins

### Users
- Anyone who uses WebBuilder
- Can propose features, report bugs
- Can vote on major decisions

## RFC Process

1. **Proposal** — Anyone can propose a change
2. **Discussion** — Community discusses for 2 weeks
3. **Revision** — Proposal is refined
4. **Vote** — Core team votes (simple majority)
5. **Implementation** — If approved, implementation begins

## Funding

- **Donations** — Voluntary contributions from users
- **Grants** — From organizations that benefit
- **Paid plugins** — Optional, community-built
- **Services** — Hosting, support, custom development

## Succession

If the original maintainers can no longer continue:
1. Core team votes on new leadership
2. If core team cannot vote, contributors elect new team
3. If no one remains, the code is archived and anyone can fork

## Decision Making

- **Day-to-day** — Core team decides
- **Major features** — RFC process with community vote
- **Breaking changes** — Require 2/3 majority of core team
- **Governance changes** — Require community vote

## Code of Conduct

- Be respectful and constructive
- Focus on what's best for the community
- Welcome newcomers
- Assume good intent
